Claims / successor

Successor

https://atep.dev/claims/successor core

Subject replaces the issuer's identity (key rotation).

Definition

Signed by the old identity, naming the new identity as subject. A verifier MAY follow exactly one hop of succession when no attestation of the old identity satisfies a rule for a signer that is the subject of a valid successor attestation. A second hop MUST NOT be followed and monitors SHOULD alert on it.

The data layout

CDDL (RFC 8610) schema of the data map of an attestation with this claim:

successor-data = { ? reason: tstr, * tstr => any }   ; issuer is the old identity

Example data in JSON form:

{
  "reason": "scheduled key rotation"
}

The whole attestation payload around data:

attestation = {
  subject: agent-id,
  issuer: agent-id,                      ; MUST equal the envelope signer
  claim: uri,
  data: { * tstr => any },
  ? evidence: bstr .size 32,
  ? evidence-uri: uri,
  id: bstr .size 16,
}
agent-id = bstr .size 32
uri = tstr

Lifetime

30 to 180 days by default, 400 days at most.

Attestations are short-lived. Issuers should keep them to 180 days with automatic re-issuance; the 180 day default is enforced by issuing tools only. A verifier rejects any attestation whose expires-at minus issued-at exceeds 400 days (attestation_lifetime_exceeded); exactly 400 days is allowed. An attestation of any type that carries evidence counts as audit-backed.
