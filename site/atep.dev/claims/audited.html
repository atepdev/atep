Claims / audited

Audited

https://atep.dev/claims/audited core

Subject passed the named audit on the given date; evidence hash required.

Definition

The evidence field (SHA-256 of the audit report) is REQUIRED; every consumer rejects an audited attestation without it as attestation_schema_invalid. Because it carries evidence it is audit-backed and may live up to 400 days.

The data layout

CDDL (RFC 8610) schema of the data map of an attestation with this claim:

audited-data = { ? audit: tstr, ? date: tstr, * tstr => any }   ; recommended layout, not enforced
; the attestation MUST carry evidence: bstr .size 32

Example data in JSON form:

{
  "audit": "SOC 2 Type II",
  "date": "2026-09-01"
}

The whole attestation payload around data:

attestation = {
  subject: agent-id,
  issuer: agent-id,                      ; MUST equal the envelope signer
  claim: uri,
  data: { * tstr => any },
  ? evidence: bstr .size 32,
  ? evidence-uri: uri,
  id: bstr .size 16,
}
agent-id = bstr .size 32
uri = tstr

Lifetime

up to 400 days (audit-backed).

This claim is audit-backed: the attestation must carry an evidence hash, and audit-backed attestations may live up to 400 days because audits are commonly annual. The issuer still publishes a revocation through its signed revocation list if the underlying audit is withdrawn.
