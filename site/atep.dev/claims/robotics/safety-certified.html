Claims / robotics / safety-certified

Safety certified

https://atep.dev/claims/robotics/safety-certified core

Subject passed the named safety standard on the given date; evidence hash required.

Definition

Subject's software and hardware passed the named standard (for example ISO 10218, ISO 3691-4, UL 3100). The evidence field is REQUIRED. Together with fleet-controller it authorizes actuation; a fleet-member with safety-certified may send an e-stop.

The data layout

CDDL (RFC 8610) schema of the data map of an attestation with this claim:

safety-certified-data = { ? standard: tstr, ? date: tstr, * tstr => any }   ; recommended layout, not enforced
; the attestation MUST carry evidence: bstr .size 32

Example data in JSON form:

{
  "standard": "ISO 10218-1:2025",
  "date": "2026-08-15"
}

The whole attestation payload around data:

attestation = {
  subject: agent-id,
  issuer: agent-id,                      ; MUST equal the envelope signer
  claim: uri,
  data: { * tstr => any },
  ? evidence: bstr .size 32,
  ? evidence-uri: uri,
  id: bstr .size 16,
}
agent-id = bstr .size 32
uri = tstr

Lifetime

up to 400 days (audit-backed).

This claim is audit-backed: the attestation must carry an evidence hash, and audit-backed attestations may live up to 400 days because audits are commonly annual. The issuer still publishes a revocation through its signed revocation list if the underlying audit is withdrawn.
