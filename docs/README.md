## How it is tested

* **Vectors are the conformance suite.** 437 vectors in 28 categories, generated by `rust/atep-core` from fixed seeds. CI regenerates them and fails if a byte differs, and `node scripts/ci/vector-counts.mjs` checks the manifest, the hashes and the counts documented in the READMEs.
* **Three implementations.** Rust passes all 437. `@atep/core` (Rust compiled to WebAssembly) and the independent Python implementation pass the 432 that do not need a stateful log or monitor and report the other 5 as skipped by name. Python was written from the spec and the vectors only.
* **Cross-check.** `vectors/crosscheck.py` recomputes several primitives with an independent library (`pip install cryptography`).
* **CDDL.** `node scripts/ci/validate-cddl.mjs` validates every vector and the JSON documents against `spec/schemas/atep.cddl`, plus mutation checks.
* **Carriers and demo.** Tests for the MCP server, the MCP, A2A, file, HTTP and MQTT examples, and the demo self-test. The ROS 2 example is logic-tested without ROS 2 and has not been run on a ROS 2 install.
* **Repository checks.** Site links and JSON-LD, no em dashes, no local paths in built artifacts, relative links in Markdown files.

The CI workflows are described in [`../.github/workflows/README.md`](../.github/workflows/README.md). No independent security audit has been done; see [`../SECURITY.md`](../SECURITY.md).
