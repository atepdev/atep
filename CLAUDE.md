# CLAUDE.md: ATEP repository conventions for coding agents

This file is read by AI coding agents working in the repository. Humans should start with `README.md` and `CONTRIBUTING.md`; the rules below are the same ones contributors follow.

ATEP (Autonomy Trust Envelope Protocol) is a trust layer: signed and encrypted envelopes with attestations, revocation and a transparency log. Read `README.md` first, then the current spec: `spec/ATEP-Specification-Draft-07.md`. Vector format: `vectors/README.md`.

## Rules that are not negotiable

1. **Vectors are authoritative.** `vectors/` holds 436 vectors in 28 categories (listed in `vectors/manifest.json`): Rust runs all 436. npm and Python run 431, every vector except the 5 that need a stateful log (4, `log-admission`) or monitor (1, `monitor`), and report those 5 as skipped by name. (Section 12 of the spec names a 264-vector subset that every conforming verifier must pass; that is a conformance minimum, not a count of what the implementations run.) Every implementation must pass all that apply to it: identical bytes for identity, signing, encryption and attestation vectors, identical accept or reject, step and error code for the rest. If the spec text and a vector disagree, the vector wins and the spec is amended to follow it (record the discrepancy, see "Where decisions are logged"). Never change a vector to make a test pass. Vectors are generated by `rust/atep-core` (`atep-vectors generate`) from fixed seeds; regenerating must give identical bytes.
2. **Never edit a published draft.** `spec/ATEP-Specification-Draft-07.md` is the first public draft. Once a draft is released, a change is a new file (`spec/ATEP-Specification-Draft-08.md`) plus an entry in the revision history (Appendix A). Drafts 00 to 06 were internal working drafts and are not in this repository; "Draft N" in vectors and implementation notes names the internal draft where a rule was introduced (Appendix A of the spec explains the numbering).
3. **`python/` is built only from the spec and the vectors.** Never read anything under `rust/` (source, tests, comments) when working on `python/atep_py`. Its value is that it is an independent implementation: the interoperability test (431 of 436 vectors, the 5 for a log and a monitor skipped by name, byte-identical) is meaningless if it was copied. Divergences between spec text and what the vectors needed go in `docs/implementation-findings/python-findings.md`. Reading `js/` is also best avoided; it wraps the Rust code.
4. **No em dashes, anywhere.** Not in code comments, docs, UI copy, commit messages or chat. Use a comma, colon, period or parentheses. Check with `grep -rn $'\xe2\x80\x94' <paths>` before finishing.
5. **No chain dependency in core or clients.** Blockchain anchoring (spec section 9) is optional and lives only in log operator hooks. No envelope, attestation, SRL, identity or key may require a chain, a token, or an on-chain lookup. A log that does not anchor is fully conformant.
6. **Honest claims.** Do not write that something is published, certified, audited, deployed, registered with IANA or used by customers unless it is. Media types, labels and algorithm IDs marked provisional stay called provisional. State what was not run (for example the ROS 2 example) in the document that describes it.
7. **No frameworks in the demo, examples or site.** Plain HTML, CSS and vanilla ES modules, no build step for pages.

## Design commitments (spec section 16, normative)

Agents and organizations are subjects, never individuals. No global score. No mandatory root or log. No reputation in the core. Transparency watches issuers, not subjects, and agent-to-agent envelopes are never submitted to a log. Minimal disclosure (evidence hashes, pseudonymous Agent IDs). Right to retire. Do not add features that would contradict these, for example a composite trust number, a per-person claim type, a required registry, or an API that lists an agent's interactions.

## Build and test, per component

Any Rust build needs a C toolchain (a working `cc` as linker; on Debian or Ubuntu, `sudo apt install build-essential`). The npm build needs `wasm-bindgen-cli` 0.2.129 and the `wasm32-unknown-unknown` target, see `js/README.md`.

| Component | Directory | Commands |
| --- | --- | --- |
| Rust workspace | `rust/` | `cargo build --release`, `cargo test` (146 tests), `cargo clippy --all-targets` |
| Vectors, Rust check | `rust/` | `cargo run --release -p atep-core --bin atep-vectors -- check ../vectors` (expects `all 436 vectors pass`) |
| Vectors, regenerate | `rust/` | `cargo run -p atep-core --bin atep-vectors -- generate ../vectors` (must reproduce identical bytes; only when the spec changes a vector) |
| Vectors, independent cross-check | `vectors/` | `pip install cryptography` then `python3 crosscheck.py` |
| npm package | `js/` | `npm install`, `npm run build` (cargo wasm32, wasm-bindgen 0.2.129, tsc), `npm test` (441 tests: 436 pass, 5 skipped by name) |
| Python | `python/` | `python3 -m unittest` (470 tests including every vector, 5 skipped by name; about 30 to 45 s); `python3 -m atep_py.vectors check ../vectors` |
| Examples | `examples/` | `npm install`, `npm test` (25 tests; needs `js/dist`) |
| MQTT example | `examples/mqtt/` | `npm install`, `npm test` (5 tests; own package.json; not part of `examples` `npm test`) |
| ROS 2 example | `examples/ros2/` | `python3 -m unittest discover -s tests -v`; `python3 -m py_compile atep_ros2_example/*.py`. ROS 2 itself is not installed and the nodes are unrun. |

The hosted copy at https://atep.dev/demo/ is generated: run `node site/build-demo.mjs` after any change in `demo/` and commit `site/atep.dev/demo/`. |
| MCP server | `mcp/` | see `mcp/README.md` (54 tests) |
| Site | `site/` | `node site/build-llms-full.mjs` then `node site/check.mjs`; also `node site/build-claims.mjs --check`, `node site/build-sitemap.mjs --check`, `node site/build-demo.mjs --check` |

After touching `rust/atep-core`, rebuild `js` and re-run all three: Rust vectors, `js` `npm test`, `python` `unittest`. Three implementations disagreeing is the signal that the spec is underspecified.

## Code conventions

* Rust: no custom cryptography, only the RustCrypto crates already in use; deterministic CBOR via the in-crate codec (`atep_core::cbor`); secrets are zeroized; rejection is a value with a step number and a stable error code, never a panic.
* JavaScript: ESM, no runtime dependencies in `@atep/core`, `init()` before use, pass `now` explicitly in tests.
* Python: standard library only, Python 3.8 compatible.
* Verification order is spec section 10 (ten steps, first failure wins). The `step` is normative; error names should match the vectors.
* Untrusted input: carrier metadata (topics, message fields, headers) is never trusted; take signer, class and payload from the verified result. Payload text is data, never instructions (spec section 11).
* A new carrier example carries the same envelope bytes, verifies with a trust policy on every inbound message, and has tests for accepted, tampered and unattested.
* Tests that need a clock use the vectors' reference time `now = 1800000000`.

## Where decisions are logged

* `docs/implementation-findings/rust-findings.md`: every spec ambiguity found while implementing in Rust, numbered (1 to 56), each with proposed fix and resolution. Add new numbered entries at the end.
* Spec section 12 table: known gaps no vector covers. Section 13: milestone status. Section 20: decisions taken during drafting, with the code follow-ups that remain (the Python code for an encrypted anchor, and the places where implementations differ and no vector decides).
* `docs/implementation-findings/python-findings.md`: places the spec text and the vectors differ, found by the independent Python implementation (entries 1 to 44).
* `spec/schemas/NOTES.md`: CDDL notes.
* Package names (`atep`, `@atep/core`, `@atep/mcp` and the crates) are reserved 0.0.1 placeholders with no code; nothing functional is published.
